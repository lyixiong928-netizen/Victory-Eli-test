## 📋 黃金工作流程

### 步驟1: 需求明確化（人類主導）

```markdown
❌ 模糊需求：
"我要一個面板管理系統"

✅ 明確需求：
功能需求:
- 支援多個UI面板的顯示/隱藏
- 支援場景切換後狀態保持
- 需要在Inspector中即時查看狀態
- 支援Undo/Redo

技術約束:
- Unity 2022.3
- 不使用靜態變數（Unity生命週期問題）
- 需要支援Prefab
- 60 FPS性能要求

測試標準:
- 場景切換不crash
- Inspector能看到所有面板
- 可以撤銷任何操作
```

### 步驟2: 架構設計（人類決策）

```csharp
// ❌ 讓AI直接寫完整系統 → 99%會有問題

// ✅ 人類先設計架構
/*
系統架構:
1. UIPanelManager (Singleton) - 中央管理器
2. UIPanel - 個別面板基礎類
3. GameMenuController - 遊戲選單控制器

依賴關係:
GameMenuController → UIPanelManager → UIPanel

生命週期:
Awake → 註冊到Manager
Start → 初始化狀態
OnDestroy → 從Manager移除

注意事項:
- 不使用靜態列表
- 所有引用都可序列化
- 支援Editor的Undo系統
*/

// 然後讓AI根據這個架構實現細節
```

### 步驟3: 小步驟實現+測試（AI輔助）

```
✅ 正確做法:

```

### 場景2: 讓AI優化現有程式碼

```
❌ 錯誤做法:
"幫我優化這段程式碼"

✅ 正確做法:
步驟1: 明確優化目標："這個Update每幀調用Find，優化性能"

步驟3: AI提供方案
步驟4: 人類review：是否真的解決問題？有無副作用？
步驟5: 測試性能：用Profiler確認改善
```

### 場景3: Debug錯誤

```
✅ 正確做法:

   - 完整錯誤訊息
   - 相關程式碼片段（10-20行）
   - 預期行為 vs 實際行為
   - 已嘗試的解決方案
步驟3: AI提供修復方案
步驟4: 理解修復原理，不要盲目套用
步驟5: 測試確認問題解決
步驟6: 記錄到專案文檔，避免重複
```

## 🎯 實戰案例

### 案例1: UIPanel系統

**錯誤過程（AI直接寫）：**
```csharp
// AI生成版本
public class UIPanel {
    private static List<UIPanel> allPanels; // ❌ 問題1: 靜態列表
    
    void Start() {
        var manager = FindObjectOfType<Manager>(); // ❌ 問題2: 無null檢查
        manager.Register(this);
    }
}

// 結果：場景切換crash，難以debug
```

**正確過程（人類把關）：**
```csharp
// 步驟1: 架構設計（人類）
/*
設計決策：
- 不使用靜態列表（Unity生命週期問題）
- 由Manager主動管理所有Panel
- Panel註冊到Manager，而非Manager查找Panel
*/

// 步驟2: 實現（AI輔助）
public class UIPanel : MonoBehaviour 
{
    private UIPanelManager manager;
    
    void Awake() 
    {
        RegisterToManager();
    }
    
    private void RegisterToManager()
    {
        // ✅ 安全的查找
        manager = DefensiveCoding.SafeFind<UIPanelManager>(
            "場景中需要UIPanelManager！請從Prefabs拖入。"
        );
        
        if (manager != null)
        {
            manager.RegisterPanel(this);
        }
    }
    
    void OnDestroy()
    {
        // ✅ 清理引用
        if (manager != null)
        {
            manager.UnregisterPanel(this);
        }
    }
}

// 步驟3: 測試
// - 空場景測試 ✅
// - 場景切換測試 ✅
// - 多次建立銷毀測試 ✅
```

## 🚀 進階技巧

### 技巧1: 契約式編程

```csharp
public class AdvancedSpriteAnimator : MonoBehaviour
{
    [SerializeField] private List<SpriteAnimationClip> animationClips;
    
    void Start()
    {
        // 前置條件檢查（Contract）
        ValidateAnimationClips();
        
        // 執行邏輯
        PlayDefaultAnimation();
        
        // 後置條件檢查
        Debug.Assert(currentClip != null, "播放後應該有當前剪輯");
    }
    
    private void ValidateAnimationClips()
    {
        if (animationClips == null || animationClips.Count == 0)
        {
            Debug.LogError($"❌ {gameObject.name}: animationClips為空！");
            enabled = false; // 禁用組件避免後續錯誤
            return;
        }
        
        for (int i = 0; i < animationClips.Count; i++)
        {
            var clip = animationClips[i];
            
            if (string.IsNullOrEmpty(clip.animationName))
            {
                Debug.LogWarning($"⚠️  動畫剪輯 {i} 沒有名稱");
            }
            
            if (clip.frames == null || clip.frames.Count == 0)
            {
                Debug.LogError($"❌ 動畫 '{clip.animationName}' 沒有frames！");
            }
        }
    }
}
```

## 📝 總結

### 核心要點

1. **永遠不要盲目相信AI的程式碼**
   - AI是工具，不是萬能的
   - 每一行都要理解其作用

2. **小步驟迭代**
   - 寫一點 → 測試一點
   - 不要累積太多未測試的程式碼

3. **使用工具輔助**
   - 程式碼品質檢查器
   - 防禦性編程工具類
   - 自動化測試腳本

4. **建立檢查清單**
   - 編碼前檢查
   - Commit前檢查
   - 週期性Review

5. **記錄問題和解決方案**
   - 每次踩坑都記錄
   - 避免重複犯錯
   - 形成團隊知識庫

### 記住

> **"AI提供速度，人類保證品質"**
> 
> **"快速失敗，快速修復"**
> 
> **"測試不是可選的，是必需的"**

---

**實踐這些原則，您就能避開AI的"假效果"，寫出真正可靠的程式碼！** 🎯
