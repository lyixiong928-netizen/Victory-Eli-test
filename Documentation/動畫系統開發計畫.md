## 💡 開發原則

### ✅ **要做的事：**
1. **先確保基礎穩固**
   - 每個功能都要測試通過
   - 確保沒有編譯錯誤
   - 使用簡單明瞭

2. **保持程式碼簡潔**
   - 一個腳本做一件事
   - 避免過度設計
   - 註解清楚明瞭

3. **漸進式添加功能**
   - 每次只添加一個新功能
   - 測試通過後再繼續
   - 隨時可以回滾

4. **以使用者為中心**
   - 操作要簡單
   - 快捷鍵要直覺
   - 錯誤訊息要明確

### ❌ **不要做的事：**
1. **不要同時改太多**
   - 容易造成混亂
   - 難以追蹤問題
   - 增加回滾難度

2. **不要過度抽象**
   - 現在不需要的功能就不做
   - 避免「萬一以後需要」的想法
   - YAGNI 原則（You Aren't Gonna Need It）

3. **不要忽略測試**
   - 每次修改都要測試
   - 確保舊功能沒被破壞
   - 記錄測試結果

4. **不要刪除工作的程式碼**
   - 用 Git 管理版本
   - 舊的但能用的先保留
   - 等新的穩定了再清理
